# WakeupHelper v3.3 Public Core

状态：公共核心发布包。版本日期：2026-08-19。

WakeupHelper v3.3 是 Freedom 原项目的署名改进版，用于在 Windows 本机整理腾讯会议和飞书妙记导出的互催 Word 文档。

## 运行要求

- Windows 10/11
- .NET Framework 4.8
- Microsoft Word 桌面版及可用的 Word COM 注册
- WPS 只有在本机提供兼容 Word COM 注册时才可能工作，本轮未将其作为发布门槛

## 本版完成的核心能力

- 腾讯会议与飞书妙记两条转换路径
- 清单驱动的 `--batch-v33` 批处理
- 明确指定主催/被催，不再以第一位说话人猜角色
- 连续同角色内容合并为一个角色块
- 主催黑字、被催蓝字，正文和 7 行表头统一为模板字体与 12pt
- 保留人工评论、红字、斜体、下划线、超链接、书签、字段和图片；受保护文字原有字体与字号也不被全局模板覆盖
- 默认词库只执行确定性的错词规则；上下文不明确的词不裸替换
- 进入互催后，若表头被催对象是 Will，则把 `被催：` 段中的独立第一人称按旁观者语义还原为 `Will`；不会全局替换普通中文里的“我”
- `我有` 按句法分流：`我有时候` -> `Will 有时候`，`我有看到` -> `Will 看到`，`跟我有讲` -> `跟 Will 讲`；主催本人第一人称、第三方直接引语和 `我们/自我/小我` 等固定词受保护
- 规则同时检查表头对象、互催阶段、角色标签、结束边界和人工痕迹；非 Will 被催文档不触发
- 评论模式与普通模式都基于原段落单次匹配，不会让一次修正结果再次触发短词规则
- 仅加入已逐条确认的精确断句：`这些。感觉`、`整个的。机制`、`先去。专注`、`自己的。提升`
- 已处理文档拒绝二次清洗，防止重复表头和累积纠错
- 单文件输出使用临时文件和原子替换；已有输出先自动备份
- Word 打开失败或关闭异常时仍会释放 COM 对象，避免隐藏 Word 进程继续锁文件
- 文件名移除 `v3.3`；有确切日期时使用 Windows 可用的 `M-D-YY`，日期不确定时不写日期

## 不会自动做的事

- 不运行泛化的 LLM 语义断句或大范围“润色”
- 不猜日期、主题、主催或被催
- 不自动删除原稿或历史版本
- 不把自然口语和有意重复一律改成书面语
- 不上传文档，不接入服务器或外部 API

## 《意识强度》边界

公共核心发布包不包含 `config/consciousness/references.json`，也不在二进制中内嵌该书的种子规则。相关 UI 保持禁用；在来源授权完成前，不作为公共分发功能。

## 包内结构

- `WakeupHelper.exe`：主程序
- `config/setting`：识别策略
- `config/template`：腾讯/飞书模板
- `config/incorrect`：确定性 ASR 错词词库
- `*.dll`：运行依赖
- `README.md`、`NOTICE.md`、`V3.3-CASE-ORGANIZER.md`、`V3.3-WILL-OBSERVER-ASR.md`：使用与边界说明
