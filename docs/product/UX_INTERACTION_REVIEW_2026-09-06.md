# StillMind：UI 与交互真实性审阅

审阅日期：2026-09-06  
代码基准：`0ba5edf7d46a113762c56e8137725d5241e7659b`，PR #3，`fix/native-integrity-deps-20260906`。  
状态：静态代码审阅 + 同版本已有 CI 截图检查；本文是修复设计，不是已实现功能，也不是新一轮真人体验或效果验证。没有修改运行代码、合并 main 或部署正式版。

## 结论

上一轮解决了大量记录、暂停、退出、输入验证与数据口径问题，但不能据此认为体验已经成熟。现在的关键不是换渐变色，而是：把只改变标签/颜色的控件，变成能帮助人完成具体练习的引导。

保留沉寂小我、自我观察与方法库的方向。不要把12种方法变成12套按键小游戏；也不要强制让用户先理解所有方法。没有点击、没有联网、没有模型调用，都不自动等于假体验。静态视觉对象、合适的提示和安静的停留也可以是完整的引导。

必须分开三件事：系统显示什么、用户选择什么、用户实际感觉什么。前两者不能代替第三者。

## 已确认的问题与处置建议

### UX01｜观电影的视角控件没有控制主要观看内容

Web `ResetPracticePlayer.tsx:126–168`：手动选择更新 `manualCinemaLens`，改变标签、高亮与辅助说明；中央分镜来自 `cinema.scenes[stepIndex]`，并不由手动视角决定。计时推进和用户选择是两条未真正接通的状态。

原生对应组件同样把中央内容设为 `instruction`，手动lens主要影响观看位置标记。

建议：保持同一事件/同一句念头不变；用户选择观看位置时，确实改变它的呈现尺度、构图及对应提示。第一版用明确按钮也可以，不必强制拖动。保留可逆操作。不显示“你已经成为观察者”。

验收：同一个step内切到观众席，中央观看对象的构图或对应内容确实变化；切回可恢复；计时不能把“系统下一条提示”记成“用户已达到某状态”。

### UX02｜残留的进度外观仍暗示不存在的测量

`ResetPracticePlayer.tsx:155` 保留固定 `w-[82%]` 的“入戏语言→旁观语言”条。登出法 `:173–179` 用固定18/38/76控制条宽。

这不是一定在伪造数据库，但视觉仍像进展或完成程度。添加“非测量”小字不能解决控件本身没有意义的问题。

建议：删掉这两类无证据进度条，不再用新标签包装它们。确有来源的时间条可以保留，但标注为播放/练习时间，不代表进步。

### UX03｜人称替代会破坏用户原句

`ResetPracticePlayer.tsx:128–133` 默认名字仍是Will，并用 `replaceAll('我', name)`；“我们”“自我”等也会被替换。

建议：不用假定姓名。保留用户原句，优先采用不改写事实的外层框架，例如“我注意到，脑中出现了这样一句话：『原句』”。这只是候选引导表达；要保留原方法中的名字替代时，需可靠识别自称并允许用户确认，不用全字替换。禁止把引语里另一个人的“我”当成用户。

### UX04｜呼吸脚本与视觉发出的指令相冲突

内容脚本要求“先不改变呼吸，数自然出现的呼气”；Web和原生组件却按 elapsedSeconds 每3秒切换吸/呼。Web同时按时间估算引导节拍，并有不同周期的装饰涟漪。

建议先决定当前这一版是“自然数息”还是“节奏引导”，不要一屏同时做两套。忠实于现有脚本时，默认不让球强制指挥呼吸；可选轻点只记点击，完全不点也正常。若采用节奏引导，球、提示词、声音/触觉必须共用一个phase，并明确是引导而非检测；需要相应更新和审阅脚本。

无论哪种，都不自动计为真实呼吸次数，不因用户不点就显示“0次有效练习”。

### UX05｜稳定法把训练目标替换成按住按钮

Web `ResetPracticePlayer.tsx:33–60,104–114`：holding使stability增加，不按则降低；到阈值后样式停止动画。CSS `illusionDrift` 本身就在真实移动图案。

因此“画面停了”的原因是程序响应按住，不是用户观察后感知发生了变化。当前加了非测量提示是进步，但不能证明该互动体现了稳定法的原本定义。

建议：停止把按住即停当作该方法的验证。首轮保留一个安全、静止或低刺激的观察对象和短提示。动态演示确需保留时，直接标为可控演示，按钮叫“暂停画面”，不叫“稳定注意”。不要默认用强烈视觉错觉测试注意，也不要据此测量心理状态。视觉素材本身需做舒适度检查。

### UX06｜念头气泡容易变成点消除游戏

`ResetPracticePlayer.tsx:141–148,181–182`：同一气泡反复点击，状态机械循环“升起→停留→落下→取消”；即使不点，透明度也跟步骤下降。预设会提供用户未必说过的负面念头。

建议：用户没输入时不替他认领念头；示例只在明确示例模式展示。练习主屏默认最多一个可选对象，或只显示“有一个念头”。一次“注意到了”是用户标记，不是系统检测。可收起字幕、撤销或什么都不做。不得把气泡消失记成念头消失，也不把清空屏幕作为完成条件。

### UX07｜聚焦、边界与开放觉察的对象/后果不够具体

意识聚焦的“杯子/杯沿高光”是固定文字，主视觉仍是抽象圆圈，不是可以看到纹理的杯子。宽恕法的滑块主要缩放圆圈。合一法默认会随step增加“已纳入”的经验，用户可能没有主动选择。

建议：聚焦提供两条清楚方式——看当前屏幕里实际可见的对象，或看现实中的自选对象；后一条不需要摄像头。边界选择可改变本次是否继续接触事件/转回现实提示，不推出已经宽恕或实际联系对方的结论。开放觉察可作为低交互引导；自动阶段写“接下来可以注意声音”，而不是“你已纳入声音”。

### UX08｜页面结构仍让练习让位于解释

旧三栏工作台不是现在首页的唯一状态，当前主入口已经有减法。但最新截图仍显示入口嵌套框多、表单在前、主按钮靠后；正式练习重复显示方法名、阶段名、计时、提示、框中分镜及观看位置说明。

建议：保留现有首页路线，把直接开始作为明确主动作；输入、评分可选展开，不必重新设计另一套入口。开始后只保留一个主要观看对象、一句当下提示，以及持续可见的暂停/停止。方法原理、12种方法、研究解释与完整反馈不要同时出现在练习现场。

### UX09｜时长版本主要是同一脚本被拉长

`practice-catalog.ts` 每个方法有一个基础脚本；非基础支持时长由 `scaleVariant` 按比例分配秒数。

这可以作为原型实现，但3/5/10分钟不等于不同深度内容。不要靠更多时长选项宣称内容深度。首轮只验收固定一分钟路径；更长版本再按真实需要编排，不新增一轮菜单。

## 推荐的最小界面改动

以下为待验证设计，不是已证实的最佳方案。

### 入口

保留品牌与方法库次入口。文案用一行意图，例如“现在，先停一分钟”。一个明确的“开始1分钟”主按钮；“想说一句”展开现有输入/语音；现有1–5自评保持可选且不造值。必要的首次边界确认继续保留。语音涉及的告知放在实际使用语音的附近，不能为美观隐藏。

不要让必须看懂“角色/观众/见证者”的人才能开始，也不暗示这个入口必然令人平静。

### 练习

一个连续场景，不是卡片套卡片。保留现在深蓝、紫色轮廓光和少量暖色，而不是重新换品牌。整体最多两层有意义容器。主指令优先，时间缩成辅助显示；同屏只保留一个与练习有关的主要动作。停止始终可访问。

影院视觉可使用已有 `inner-cinema.svg` 或简洁的独立背景层，但需要把它接到真实播放器而不只放预览。真正重要的是“这还是同一句话，但观看方式变了”，不是背景一定要照片或AI视频。

### 结束

优先允许离开，不能先完成长问卷。保留既有缺失评分与中性结束语义。量表、复用意愿、文字反馈和复制反馈逐步展开或由主持人另行收集，不再首屏全部铺开。若加入一句“有变化/没变化/更不舒服”的主观反馈，需要与数值差分分别存储，不能覆盖或伪造另一种证据。

“接下来可以先不回复”是建议；“你选择稍后回复”是意向；“已经没回复/完成行动”必须另有证据，默认不记录。

## 先做的一条完整体验：观电影法

1. 用户输入一句话或选择不输入。原文只用于本次，不发送统计；没有输入就不给他安排一个负面念头。
2. 把这句话放到一个清楚的“银幕”对象中；第一句引导只说明“先把这句话放在这里”。不解释人格或深层动机。
3. 点击“退远一点”改变同一银幕的空间关系：不铺满、出现观众席或边界、字幕仍保留。可点击切回；不强制拖动。
4. 给短暂停留；计时只控制提示，不判定用户做到了观照。用户可以没感觉、跳过、停止。
5. 结束后只由本人可选报告实际感受。没有报告就空着，不出“你已经退出剧情”的统一结论。

接受标准不是让每个人都变轻松，而是：知道怎么开始；能看出自己的操作改了什么；不被分配未说过的想法；没感觉/不舒服能直接结束。

## 12种方法：处理方式，不是12套新项目

| 方法 | 当前应做什么 |
| --- | --- |
| 观电影法 | 第一优先：同一内容真正改变观看构图与对应提示；保留可逆选择 |
| 呼吸法 | 第一优先：统一自然数息或节奏引导的内容/视觉，不显示推算呼吸 |
| 凝视法 | 保留稳定对象与自愿回归；点击统计退出主视觉，不当成绩 |
| 觉察法 | 取消强制点落气泡，不替用户填负面念头；只提供自愿标记 |
| 人称替代法 | 修复全字替换、默认Will及固定82%条；确保不改错事实 |
| 登出法 | 去掉固定数值条；真实切换本次展示/暂停接触事件，而非只换标签 |
| 内观法 | 可选身体落点改变具体提示；允许没有感觉与外部对象替代，不自动填体验 |
| 宽恕法 | 保留主动选择和边界；不要用圆圈缩放作为效果，不默认推荐给初次用户 |
| 合一法 | 可保留安静、低交互的引导；“系统提示”与“用户已注意到”分开 |
| 意识聚焦法 | 提供确实看得见的对象/细节，或清楚转向现实对象；别只改名词 |
| 稳定法 | 停止用按住人为减速证明注意稳定；方法实现需回到已定义的观察目标 |
| 意识抽离法 | 可以保留示意缩放，但称为视觉提示；保留回到现实环节，非心理测量 |

保留12种方法目录与访问路径；没有把握的互动先诚实提供文字/静态引导，不自动把方法本身判为无效。不以“高级”排名人的状态。

## 实现与回归边界

- 先保留 `0ba5edf` 为工程基准；本次没有动它。
- 后续只做一个可回退的UX补丁，优先改Web播放器与对应原生组件，保持domain的资格/计时/同意/结束语义。
- `sceneIndex`、`selectedLens`、`guidePhase`、`userMark`、`selfReport`分开。展示进度不得流入心理效果字段。
- 不强加模型调用、摄像头、麦克风、穿戴监测或新的云端日志来证明“真实”。AI只在明确启用和有适合任务时可选使用，预设来源继续如实标注。
- 装饰动画和核心引导分开；尊重减少动效；无动画时仍能完成任务。
- 在已有119项工程测试之外新增语义验收：切镜头改主要内容/构图；不存在固定心理进度条；不输入不出现认领式负面字幕；自然数息不强制节拍；不点击也能结束；正文原句不被盲目替换；暂停/停止/退出始终有效。
- 较小屏幕、大字号、键盘弹出、减少动效、屏幕阅读器模式下检查主要操作。自动化证明操作，不证明心理效果。

## 真人检查：先看3位独立使用，不做统计显著性结论

沿用既有内测协议与授权边界。主持人不先讲原理，只问：第一步会做什么？点了之后什么变了？没感觉时怎么结束？看不懂、无变化、退出和更不舒服都保留。3人的反馈只定位可用性，不证明有效或市场成立。

## 外部参考（设计原则，不是StillMind效果证据）

- Apple HIG — Feedback：反馈帮助理解状态、动作结果与下一步。https://developer.apple.com/design/human-interface-guidelines/feedback
- W3C WCAG — Animation from Interactions：非必要交互动效应可关闭；动效可能造成干扰或不适。https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html

优先原则：可以模拟影院，不能模拟用户已经看开。让画面配合用户的一次练习，不让用户配合一场自动播放的表演。
