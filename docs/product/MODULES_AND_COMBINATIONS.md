# 项目结构：三个模块与可组合形态

更新：2026-09-07。状态：创始人补充的产品结构与边界；不是已实现架构或授权证明。本页取代把整个项目缩成“只有App1”、或把三个模块说成三个已上线App的旧表述。

## 1. 创始人明确的三个东西

| 模块 | 含义与历史名称 | 在本仓库可确认的状态 |
| --- | --- | --- |
| A｜沉寂小我 / StillMind | 历史App1：沉寂小我练习，可结合意识强度相关点。服务当下暂停、自我观察与持续实践 | 已有Next Web和Expo客户端、12方法目录、规则推荐、计时、记录和反馈；体验语义仍有待修项 |
| B｜复盘工具 | 历史App2：潜催复盘，可结合意识强度相关点；历史例子为内部学员上传自己的文档，形成对应提升参考 | 本仓库的Reflection/周报只处理练习会话，不等于完整的材料上传、分析、生成指南产品。独立B代码和实际能力待Codex核验用户本地/其他明确仓库；不因本仓库没看到就断言用户没有 |
| C｜根据古零书籍/文章整理的知识库 | 可独立学习/检索，也可作为A、B的内容与方法层 | 用户说明已有/在整理此资产；本仓库可见来源元数据、研究整理与方法映射。完整语料、切片、索引、引文验证与授权不能由这些文件证明 |

历史App1/App2名称来自2026-06-29的用户沟通；两个方向当时都有意识强度相关点，不是App2独占知识层。本页只保留必要产品关系，不附私人聊天、书籍正文或他人材料。

## 2. 定位不能再被讲扁

A不是“无论如何都要删掉方法体系，只做一分钟工具”。一分钟是降低首次操作成本的入口；背后的方向仍是沉寂小我、自我观察、观照与长期实践。对外说明要让人知道正在参与什么，而不是把真实目的隐藏后再引导进入社群。

“是否有帮助、是否更不舒服”由用户反馈；系统不宣布其已觉醒、已退出小我，亦不以分数给人划等级。学习框架中的术语不自动等于可测得的个人属性。

## 3. 七种组合：能力与内容要分开验收

这些是可配置的产品形态规划，不表示已有运行中的开关、独立包或数据互通。

| 组合 | 具体例子 | 主要待确认项 |
| --- | --- | --- |
| A | 用户不写经历或写一句，做短练习，能停下并可选记录 | 现有脚本逐项来源审查；不能先声称“纯原创无授权问题” |
| B | 材料整理为事件、本人描述的反应、待确认问题与下一步参考 | 通用复盘是可行产品方向，不是本仓库已实现功能；确认输入同意、保存/删除及人工审核 |
| C | 查某个概念，返回有出处的解释或索引 | 知识库展示、原文/改写、检索片段、使用人群和授权范围 |
| A+C | 在短练习后查看获准的相关知识点或方法说明 | A中哪些脚本/解释来自C；独立审核，不以“关闭检索”替代来源隔离 |
| B+C | 内部学员上传自己的复盘，对照获准的知识点，生成带出处、可修正的学习参考 | 历史App2主要例子；不输出权威人格/意识等级，不推断隐藏创伤；资料、上传文档与模型处理分别确认 |
| A+B | 用户同意后，把多次练习记录交给周期复盘，再由本人选择下一步练习 | 现有本机会话周报不等于这个跨模块流程已接通；先明确字段和可撤回的数据边界 |
| A+B+C | 当下练习→经同意的周期复盘→获准知识参考→本人选择后续练习 | 长期方向；不作为下一次Codex自动开发全部模块的任务 |

重要区分：技术能独立运行 ≠ 内容一定独立创作；未直接加载C ≠ 没有受C影响的表达；研究元数据存在 ≠ 生产检索库完成；学员自己的文档 ≠ 可自动公开或发第三方模型。

## 4. 当前实现与下一步

本仓库当前优先修A的体验真实性，保留已经验证的会话、安全、计时、隐私和存储。先做一个可回退的UX补丁，不并行创建B/C服务或拆成多个仓库。对B/C先做清点：在哪里、版本是什么、哪些已运行、哪些只是笔记；未确认就写未确认。

下列数据连接只是规划：A的记录流向B、B的结果推荐A、A/B从C检索。没有用户同意、字段边界和来源许可时，不自动实现云同步或把当前私人记录交给模型。

## 5. 给资料审核方的说明要按组合回答

资料审核需要四件事：哪个组合、谁使用、具体输入输出例子、用到哪些资料/媒介。本轮历史定义已明确，不再反问App1/App2分别是什么；也不再笼统说“一律只谈App1”。

允许内部某组合使用，不自动等于允许其他组合、外部测试、商业分发、翻译、TTS、原文检索或第三方模型处理。收到“请补计划/先看看”不是本项目的许可凭证。没有证明的范围保持待确认；不是一概判定所有通用概念均不可用。

## 6. 15人计划的正确口径

15人是已有的候选测试规模，不是15人已报名/完成。原方案中的“5位社群用户”不自动等于5位潜催内部学员；其他分组也不能未经核实就宣布为潜催外部。名单身份、招募范围和每人拿到的版本尚需确认。

需要逐批写清：组合ID（A / A+C等）、构建提交、内容版本、来源许可范围、内部/外部身份、是否有主持帮助。涉及待授权内容的组合不能默认开放给外部，内部身份也不是替代许可的自动通行证。拟不带C的A版本，先审查实际脚本，确认确实满足拟定范围再分发。
