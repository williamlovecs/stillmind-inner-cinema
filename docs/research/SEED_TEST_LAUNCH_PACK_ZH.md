## 样本与记录

按原协议：5位已有社群用户、5位工作/产品设计同行、3位非圈内的正念/日记用户、2位不喜欢冥想App或AI陪伴的怀疑者。每人首次体验一行，S01–S15；社群熟悉度不等于市场验证。

真实记录只存私密目录，不进Git。复制现有 `seed_user_results_template.csv`；保留原表头。首次结果与48–72小时随访更新同一行，不新增同一人的重复行。联系人另存，不写进结果CSV。

每批附版本记录：head SHA、测试URL、Web/Expo Web/原生、设备与浏览器大类、是否有主持人帮助。Web没有原生Reflection/Profile导出菜单，不能写“已找到”；按实际记partly/no并注明缺项，不能据Web数据宣称iOS验收完成。

## 群内可发（确认开放后填入真实链接）

> 我把StillMind这一版固定下来了，想找几位朋友试一下。它是一个短时暂停和自我观察练习，先做一分钟，不用先学12种方法。
> 这次主要想知道：你能不能自己用起来、哪里烦、有没有更不舒服，以及下次会不会真的想起它。没变化、关掉了，都算有用反馈，不用给面子。
> 测试链接：［核验后的本轮链接］。不用写私人经历，也不需要付费。想参加这轮的私聊我，我分批发说明。

群规则可直接补一句：

> 这个群只做产品体验和反馈，不做诊断或情绪危机处理。不发自己或他人的隐私、不劝别人坚持不舒服的练习、不转发群友内容、不拉人头。随时可以退出；要反馈具体问题请私聊，不必在群里讲经历。

## 主持人照读：少解释，不教学

> 今天测的是产品，不是你的练习水平。你可以用一句泛化的小事，也可以不输入。不舒服、看不懂或不想做，都可以停止。结束后说真实感觉即可，不需要达到某种状态。我只记页面、操作和不含隐私的反馈，可以吗？

不要说“你觉察到就说明有效”“继续做就会消散”，不要预告应该放松，也不要追问创伤或人物关系。用户报告不适时回应：“收到，我们先停。你不需要继续，也不需要解释原因。”

## 每人一次，分三段

**A. 核心一分钟（先观察自然使用）**：打开入口，自己决定是否输入/评分并开始。记录第一处停顿、开始前耗时、是否需要解释。不要先带着做呼吸。停止就是停止，不劝完成。被卡20秒以上才给一次操作提示并记录帮助。

**B. 功能检查（与自然使用分开标记）**：按原协议检查暂停/继续、诚实结束、可选后评分/行动；再检查隐私/支持/删除/导出。功能指令导致的停顿不算自发流失。缺失功能如实记，不用主持人代操作算成功。

**C. 体验反馈**：先问“你觉得这是干什么的？”“什么时刻会打开？”“哪里太多或不舒服？”再问“比刚才，多了一点选择、差不多、更不舒服，还是说不清？”评分可不填。最后问是否可能再次使用及隐私担忧。深层理论、商业介绍放在反馈之后，也可不讲。

## 数据口径

当前产品自评是1–5，不能和旧0–10直接混算；主持人的六维1–5可用性评分也不能冒充用户前后状态评分。空白就是未回答，不写0、不填默认值。自报better不等于临床效果；差值下降也不能证明因果。

`after_check_result`按原协议使用more_choice / same / worse / stopped；说不清或未回答留空，在非敏感备注中说明。安全三列必须完成观察后明确yes/no；不知道就留空，不能默认no。不要填人名、触发原话、诊断、联系方式；默认不录音，不截含原话屏幕。CSV本机运行：

```bash
npm run analyze:seed-users -- /path/to/private/seed_user_results.csv
```

脚本新增INVALID_DATA：重复ID/坏格式要先纠正。输出含备注汇总，也只在私密环境看。

## 暂停与扩测：沿用原阈值，不等到第15人才停

任何严重安全关注先暂停该轮并联系现实支持；同一方法2人更差，停止分发该方法复核；4人因文字/困惑停止，或3人误认诊疗/建议，先改产品，不增长。不要删除不利行或用后来满意者冲淡它们。

满15位独立首次记录后，至少8完成、5报告更多选择、10理解非临床边界、8能找到隐私/支持/删除/导出，且无未解决严重关注，才可建议进一步测试。脚本GO只是原协议的扩测建议，不是签名/授权/上线审批；Web缺项不能被GO洗掉。安全观察缺失会得到INSUFFICIENT_DATA。喜欢概念却说不出用的时刻，也应停下复核。

## 48–72小时随访（手动发送，尚未安排自动消息）

> 前两天那个StillMind，后来你有没有自己再打开过？没用也正常。用过的话只告诉我大概什么场景；没用的话，是没需要、想不起来，还是上次体验不合适？不用讲事情细节。

区分主动复用、被提醒后复用、未复用、未回复；未回复不是拒绝，愿意再用不是已经复用。不要先提醒他使用再问“是否自发使用”。

## 商业问题放在体验之后

有真实使用场景且认为有帮助的人，再按 `PAYMENT_INTERVIEW_PROTOCOL.md` 约至少5次合格访谈。既有订阅/21天/陪伴组价格只是测试假设，不是已上线套餐、营收或承诺；本轮不收钱。

15人结束只出一页：人数/版本/分群、完成与帮助、前三卡点、更差/停止、真实复用、下一项最小修复、是否继续。最多依据新证据改一个主要体验假设，不再同时让多个AI给相反的UI方向。
